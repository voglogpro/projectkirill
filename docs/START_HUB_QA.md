# Стартовый экран KIRA — 5 сентября 2026

## Пользовательский путь

1. Инструкция с тремя шагами — первый блок после входа.
2. Продолжение облачных проектов и пробных копий на устройстве.
3. Четыре бесплатных конструктора: текстовый бот, бот + Mini App, полный набор, сайт.
4. Каталог десяти сценариев: поиск, категории, живой симулятор, использование шаблона.
5. Тарифы на запуск внизу; верхняя ссылка ведёт к ним. Четыре карточки обозначают форматы проекта, а не четыре разных подписки. Реальные планы не изменены: 350 ₽ за одного бота, 650 ₽ — до трёх.

На ПК конструкторы и варианты запуска располагаются в четыре колонки, на телефоне — 2 × 2 без карусели. Сохранены Onest/Unbounded, тёмная палитра KIRA и фиолетово-голубой акцент. Каталог также используется на главной; видео не заменялось.

## Бесплатные черновики и защита данных

- Редакторы и предпросмотр открываются без оплаты, даже если единственный облачный проект уже занят.
- Пробные копии имеют отдельные UUID и ключи браузерного хранилища, изолированные по аккаунту. Они не отправляются в облачный autosave и не перезаписывают существующий проект или его сценарий.
- URL `?draft=<uuid>` восстанавливает такую копию после перезагрузки. Она доступна только в этом браузере/профиле, пока его данные не удалены; это не облачная резервная копия.
- Если браузер запретил запись или исчерпана квота, редактор сохраняет данные только в памяти вкладки и показывает предупреждение. Закрытие вкладки потеряет эти несохранённые изменения.
- Кнопка запуска сначала предлагает явно сохранить новый проект в аккаунт. Занятый облачный лимит не блокирует дальнейшее бесплатное редактирование.
- Перенос восстанавливается после частичного сетевого сбоя по детерминированному slug; повторно записываются актуальные страницы/сценарий. Активные и опубликованные проекты защищены от замены пробной копией.
- Мастер запуска публикует сохранённый сценарий перед подключением бота. Реальную оплату и Telegram-активацию эта QA-проверка не выполняет.

## Границы возможностей

Это собственные редактируемые сценарии KIRA, не загрузка или выполнение сторонних архивов. Сценарии не обещают автоматическую проверку уроков, напоминания или внешние интеграции, которых нет в runtime. Публикация отдельной страницы сайта сейчас также требует подключённого Telegram-бота; это указано рядом с тарифами.

На [BotHost](https://bothost.ru/katalog-botov) использованы как референс категории, карточки и понятный переход к запуску. Публичная кнопка «Хостить» ведёт к регистрации; доступность скачивания исходников и запуска конкретного стороннего архива не подтверждалась. Отказ от скрытой горизонтальной ленты согласуется с [разбором мобильных каруселей Nielsen Norman Group](https://www.nngroup.com/articles/mobile-carousels/).

## Проверки

```powershell
npm.cmd test
npm.cmd run build
node tools/preview/build.mjs
# Указать модуль Playwright, если он установлен вне workspace:
# $env:KIRA_BROWSER_MODULE='C:\path\to\node_modules\playwright'
# Локальный Vite должен работать на 127.0.0.1:5174.
node tools/qa-start-hub.mjs
node tools/qa-flow-editor.mjs
```

- Unit/API tests: каталог, достижимость веток десяти сценариев, изоляция хранилища, повреждённые данные, quota/security errors, восстановление частичного переноса.
- Browser QA: 1440 × 1000, 390 × 844, 320 × 720; порядок секций, сетки, якорь тарифов, отсутствие горизонтального overflow, фильтры, симулятор и возврат фокуса.
- На mock-аккаунте с одним занятым облачным проектом проверены все четыре конструктора, реальные правки, reload, неизменность исходных данных и отсутствие API-записей при бесплатном просмотре.
- Повторно проверены линии/undo/redo/сохранение desktop-редактора, мобильные связи, видео при смене ширины, последовательность облачного autosave.
- Chrome DevTools MCP использован для визуальной проверки готовых экранов. Скриншоты создаются в игнорируемой папке `preview/qa/`.
- Исходная композиция видео проверена HyperFrames lint: 0 ошибок, 0 предупреждений. Новый ролик не генерировался.

Production build проходит; остаётся предупреждение Vite о крупном общем JS-бандле кабинета. Mini App сохраняет отдельный лёгкий бандл. Деплой на BotHost выполняет владелец. Внешний Claude-артефакт этим прогоном не публикуется: пересобирается локальный `preview/index.html`.
