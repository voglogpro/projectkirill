# TMA Studio

SaaS-конструктор Telegram Mini Apps: человек без кода собирает приложение из
блоков, платит за подписку, платформа сама подключает бота и держит хостинг.
Тарифы: 350 ₽ — один бот, 650 ₽ — три бота.

## Как работаем

- Отвечать по-русски и коротко. Экономить на объяснениях, не экономить на работе.
- Не спрашивать подтверждений на обычные правки — решать самому и делать.
  Спрашивать только там, где ошибка дорого стоит и её нельзя откатить.
- Правки идут в код продукта (`src`, `apps/web`, `apps/miniapp`), не в макет.
- После правки: собрать, пересобрать стенд, опубликовать в тот же артефакт,
  одной-двумя строками сказать что изменилось.
- После каждой правки коммитить и пушить **в `main`** — Bothost собирает
  приложение именно из `main`, и владелец деплоит сам, не дожидаясь ответа.
  Ничего не копить локально и не оставлять в отдельной ветке.
- Ссылка на стенд не меняется:
  https://claude.ai/code/artifact/782991ae-84b1-4c9d-9188-17d63f3549fd

## Команды

```bash
npm run typecheck
npm test                              # backend + @tma/web + @tma/miniapp
npm run build                         # API + обе витрины
node tools/preview/build.mjs          # собрать preview/index.html (стенд)
```

Локальный прогон всего стека (нужен PostgreSQL):

```bash
service postgresql start && su postgres -c "createdb tma_builder"
cp .env.example .env                  # SESSION_JWT_SECRET — 32+ символа
DATABASE_URL=postgres://postgres:postgres@localhost:5432/tma_builder node index.js
```

## Устройство

- `src/` — Fastify + Zod + PostgreSQL: auth, проекты и страницы (JSONB),
  биллинг, подключение бота, webhook и worker Telegram.
- `apps/web/` — React-кабинет: лендинг, дашборд, редактор, мастер запуска.
- `apps/miniapp/` — рендерер Mini App без UI-фреймворка (~4 kB gzip). Он же отдаёт
  публичный сайт на `/s/:publicId` — тот же релиз, другая раскладка.
- `motion/` — HyperFrames: анимации для сайта. `npx hyperframes render .` в
  `motion/videos/<проект>`, готовый файл кладём в `apps/web/public/media`.
- `tools/preview/` — стенд: собирает боевые бандлы в одну HTML-страницу поверх
  браузерного стенд-бэкенда. Не импортируется продуктом.
- `docs/API.md` — маршруты, `ARCHITECTURE.md` — модель данных и границы.

## Правила кода

- Схема страницы — единственный источник правды о блоках
  (`src/domain/page-document.ts`). Новый блок добавляется и в неё, и в
  рендерер Mini App, и в инспектор редактора.
- Никаких внешних хостов в дефолтах контента — приложение должно открываться
  в Telegram на слабой связи.
- Токены ботов только в зашифрованном виде, в логи не попадают.
- Палитра одна на весь продукт: токены в `:root` (`apps/web/src/styles.css`),
  фон `#0A0A12`, плитки `#12121F`, акцент — градиент `#7C5CFF → #2AABEE`.
  `color: white` на цветной подложке пишем как `var(--on-accent)`.

## Хостинг

Bothost, ветка `main`, база — внешняя PostgreSQL (Neon). Инструкция:
`docs/BOTHOST_DEPLOY.md`. После пуша владелец жмёт **новый deploy**, а не
restart. На каждого бота отдельный сервер не поднимается: все боты приходят на
один webhook и различаются по `publicIntegrationId`, все Mini App отдаёт один
TMA Core — сотня клиентов живёт в одном процессе.

## Цель продукта

Всё должно работать без участия владельца: человек сам создаёт бота, собирает
сценарий, подключает Mini App и платит. Любой шаг, где нужен владелец, — это
дефект, а не «пока так».

## Отложено (не начинать без команды владельца)

ЮKassa и автопродление подписки, юрлицо и оферта, KMS вместо `LocalAesKek`,
Google Cloud Run (база там платная, а воркер-цикл не переживает scale-to-zero).
